# 地图编辑器（模块六）· 设计文档

> 给维护者看的。面向用户的功能介绍在 [README.md](../README.md)；
> 实现细节与踩坑在 [ENGINEERING.md](ENGINEERING.md) 的「模块六」一节。

## 一、为什么推倒重来

第一版模块六把「导入 tileset → 切分 → 地形族与掩码 → 多图层 → 导出 Tiled」做成了一条
四步流水线。工程上它是对的（全本地、零计费、导出可校验），但**真机反馈一致是「门槛太高」**：
界面上全是自造词（图集 / 切分 / 图块序号 / 地形族 / 掩码 / 优先级 / 变体种子 / 高度偏移 / chunk），
用户要先学会一套词汇才能画第一格。当时的补救是「就地小字 + 悬停解释 + 空态四步引导」，
等于承认了「先解释，再动手」这条路走不通。

于是这一版换参考物：[AsPJT/AsLib](https://github.com/AsPJT/AsLib/tree/master) 的 **RPG Map Maker**
（C++ / DxLib，CC0）。它只有一个窗口、11 个图标按钮和一块调色板，没有任何一个自造词，
却能画出带自动连接的地图。本模块按它重做：

| | 第一版（已删除） | 本版（AsLib 风格） |
|---|---|---|
| 上手路径 | ① 图集 → ② 规则 → ③ 地图 → ④ 导出 | **选一张素材图 → 直接画** |
| 素材形态 | 用户填格子尺寸 / 边距 / 间距，再手动配族与掩码 | **新增素材时填一次就定死**（留空 = 按图片尺寸自动识别）；四个带悬停解释的按钮选用法，之后**只能删掉重来** |
| 地图尺寸 | 只能正方形（预设 32 / 64 / 128） | **宽高自由填**（1~512 格各填各的）；素材格子也能自由填（宽/高像素，实时显示切出几列几行几块） |
| 自动连接 | 地形族 + 16/47 掩码 + 优先级，全部手工配 | **自动**：同一张素材图自己跟自己连，零配置 |
| 格网 | 正方形俯视 + 2:1 等距 | 正方形俯视（环绕） |
| 地图 | 多张地图 + 多图层 + 每层高度偏移 | 单张地图 + 多图层（上下切层按钮，AsLib 同款） |
| 导出 | 分层 PNG + 自有 JSON + Tiled `.tmj`/`.tsj` | PNG + 存档 JSON |
| 界面 | 长文案 + 阶段条 + 名词速查 | **一屏、纯图标、无阶段条、无术语** |

**已删除的能力**（不给「进阶模式」留后门，旧实现留在 git 历史里）：2:1 等距、多地图、
图层高度偏移 / 不透明度 / 层类型 / 锁定、地形族与掩码编辑器、掩码覆盖率验收、Tiled 导出、
带图例的自有 JSON、切片 contact sheet 预览。

## 二、四条架构决策（沿用，全部保留）

### D1 · 客户端零几何决策

宿主算出**绘制计划**（每项 = `{层, 格号, 图块序号, 目标像素, 不透明度, 可选循环帧}`），
客户端只做 `drawImage`；导出 PNG 执行的是**同一份计划**。界面里自己写的几何只有
§七 那四个函数。

为什么必须这样：旧模块把「变体怎么挑、裁剪偏移多少、锚点在哪」写了两遍（宿主一遍、界面一遍），
两边只要有一处口径不同就是「点到的格子和涂到的不是同一格」，而且**不报错**。

### D2 · 画布渲染，不是每格 DOM

单个 `<canvas>` + 视口渲染（只画可见 chunk），计划按 32×32 的 chunk 下发。
**chunk 的划分与「哪些 chunk 可见」也由宿主算**（`mapPlan({view})` 回 `visibleKeys`），
所以界面里连 chunk 计算都没有。

### D3 · 宿主是唯一写者

界面只发 op（`paint` / `fill` / `rect` / `replace`），宿主应用后回传**需要丢弃的 chunk 列表**
（`dropKeys`，见 §五）。撤销/重做是宿主侧的逆操作日志，界面不维护撤销栈。

### D4 · 派生数据不落盘

自动连接的形状判定、动画帧、视口范围、chunk 一律现算。落盘的只有：素材原图、
`project.json`（元数据）、`map.json`（每层每格的语义序号）。没有任何缓存字段。

## 三、数据模型

```
<DSH_HOME>/game-material-master/map-jobs/<项目 id>/
├── project.json          元数据：网格、素材清单、阶段、日志
├── map.json              唯一一张地图：图层元数据 + 每层数据（0 = 空）
├── tilesets/<tsId>.<ext> 导入的原图（原样保存，不改写）
├── preview/*.png         验收图：地图渲染图
└── export/<安全名>/      导出：map.png / map.json / manifest.json（+ tilesets/ 与 <地图名>.zip）
```

```ts
MapProject { id, name, createdAt, updatedAt, grid, tilesets[], stages, logs[], reviewMode? }
MapGrid    { tileWidth, tileHeight, wrap }                       // wrap 默认 true
MapTileset { id, name, file, imageWidth, imageHeight, cell, shape, animRows, variants, tiles[] }
MapTile    { id: "t{x}_{y}", rect, name, mask?, shape?, variant?, frame? }
MapDoc     { id, name, cols, rows, layers[], data: Record<layerId, number[]>, markers[] }
MapLayer   { id, name }
MapMarker  { id: "m1", r, c, name }   // 标记点（「标记层」；编号不落盘 = 下标 + 1）
图层数据    number[]   // 长度 cols×rows，0 = 空，其余是**全局图块序号**（1-based）
```

默认三层：**地理层 / 装饰层 / 建筑层**（新建项目即如此）。老项目只在「还是出厂的两层名
`图层 1` / `图层 2`」时自动升级成这套名字 + 补一层建筑层 —— 用户改过名的文档一个字都不动。

**标记不放进 `layer.data`**：`data` 每格只装得下一个图块序号，而标记要带名字，
另存一份名字表就是「同一件事两处存」（旧模块的三份缓存各自过期过）。所以标记是**自己的源数据**，
在图层卡里占一行固定的「标记层」，不进 `layers[]`（否则渲染、序号平移、清层、裁剪尺寸
这些遍历图层的代码都要为它加特例）。

三条要点：

1. **图块 id 由矩形派生**（`t{x}_{y}`），不是数组下标 —— 改素材形态之后同一个矩形的
   人工字段（`mask` / `name`）仍然挂在同一个 id 上（`buildTiles` 按 id 合并）。
2. **图层数据存全局图块序号**，序号 = `flatTiles()` 的顺序（素材顺序 → 切片顺序）。
   改形态或删素材会让序号平移，宿主按「素材 id + 图块 id」把每张地图的格子重新映射；
   对不上的格子清零并计数，**不静默错位**。
3. **A2 拼块素材里，`tiles` 的元素是「小格」而不是整格**：一张 A2 图会被切成
   `(imageWidth / (cell/2)) × 10` 个小格，每个小格标着 `shape`（块行 0..4）、
   `variant`（块列）、`frame`。渲染时一格要取 4 个小格（见 §六）。

## 四、环绕（toroidal）

AsLib 的地图**四周相接**：相机、命中测试、自动连接的邻域判断全部取模，
画到右边界接着左边界。本版照做，`MapGrid.wrap` 默认 `true`（可关）。

- `pointToCell` 在环绕下把越界点折回图内；但**客户端只认地图自己那一份**：
  未取模格号落在 `0..cols` / `0..rows` 之外的指针位置一律不算命中 —— 图外不落笔、不悬停
  （用户报过「画超过右边缘时左边缘被着色」，就是折回导致的）。
- 相机被**夹在地图内**（`clampPan`）：`pan`（画布左上角落在地图的哪个像素）取值范围是
  `0 .. max(0, 地图 - 视口)`。地图比视口小 → 钉在左上角（`pan = 0`，「地图左上角 = 画布左上角」）；
  比视口大 → 能滚，滚到地图右下角贴住画布右下角就停。所以界面上**不会**再出现环绕出来的副本，
  环绕只剩数据层语义（自动连接邻域、脏块、导出铺一次）。
- 绘制范围各维长度**最多一张地图那么大**（`viewCellRange` 会截断）—— 内容会重复，
  多画只会把计划撑爆。宿主仍支持「起点越界 + 同一格出现在多个像素位置」这种请求
  （`verify-map` / `-pipeline` 里有用例），只是相机被夹住后客户端不会再发出这种视口。
- 导出**不环绕**：`buildPlan` 不传 `range` 时按 `0..cols` / `0..rows` 算，PNG 就是这张图本身。
- 洪水填充（油漆桶）**不跨接缝**（AsLib 同款，在平面数组上做）；这一点写进界面帮助。
- 改一个格子会影响**环绕邻域**的外观（画第 0 行 → 最后一行长出过渡边），
  所以脏块计算也必须环绕（见下）。

## 五、编辑协议：op + dropKeys

```ts
applyMapOps({ projectId, ops, stroke?, have?: string[] })
  → { changed, skipped[], dirtyChunks[], dropKeys[], canUndo, canRedo }
```

`ops` 四种（语义与第一版一致，**未变化**，对话面契约不变）：

```ts
{ kind: "paint",   layerId, cells: [{ r, c, tile }] }   // tile 0 = 清空
{ kind: "fill",    layerId, r, c, tile }
{ kind: "rect",    layerId, r0, c0, r1, c1, tile, filled }
{ kind: "replace", layerId, from, to }
```

校验**一律不抛**，写进 `skipped`（中文原文）；`stroke` 让同一次拖拽的多个批次**并成一条撤销**。

**`dropKeys` 是这一版新增的关键设计。** 环绕之后，客户端缓存里的 chunk key 是
「未取模」的（可能是 `-1,0`），而一次编辑影响的是**规范** chunk 集合（含环绕邻域）。
让界面去换算这件事，就等于把几何又抄了一遍。所以：界面每次查询都把自己的缓存键
（`have`）报上来，宿主对每个键做 `canonicalChunk` 映射后判断是否命中变更集合，
只把**真正失效的那些键原样返回**。界面只做「删掉这些键 → 按 `visibleKeys` 补缺失的」，
一个坐标都不算。

`mapPlan({ projectId, view, have?, layerIds? })`：

```ts
→ { grid, cols, rows, bounds, visibleKeys[], chunks[], legend, fps, frameCount,
    truncated, warnings[] }
```

- `viewCellRange` → `chunksInRange` → `visibleKeys`（宿主算，可为负 key）。
- 只对 `visibleKeys - have` 生成 ops。
- 可见 chunk 超过 `MAX_PLAN_CHUNKS = 256` 时截断并 `truncated: true`，界面提示
  「现在缩得太小，画布只画了一部分（放大一点）」。
- `layerIds` 用于**单层预览**：过滤由宿主做，界面不许自己筛 ops。

### 标记点的 op

和画笔走**同一条通道**（`applyMapOps`），所以撤销栈、脏块（`dropKeys`）都是现成的：

```jsonc
{ "kind": "marker", "op": "add",    "r": 3, "c": 3, "name": "宝箱" }  // id/name 可省，宿主发号
{ "kind": "marker", "op": "remove", "id": "m1" }
{ "kind": "marker", "op": "move",   "id": "m1", "r": 4, "c": 4 }
{ "kind": "marker", "op": "rename", "id": "m1", "name": "出口" }
```

- **一格最多一个标记**：重复放置进 `skipped`（文案说清是第几个），不静默顶掉。
- **编号 = 数组下标 + 1**（用户选的策略：连续编号，删了自动重排）。所以增删之后
  `applyOps` 会把**后面那些标记的格子一并标脏** —— 不标的话屏幕上留着旧号码。
- **改名不脏任何格子**（名字不上画布），但它真的改了文档：靠 `ApplyResult.touched`
  让上游照样记一步撤销（只看 `changed > 0` 的话，改名会「生效了但撤不回来」）。
- 环绕打开时，越界 / 负数格与图块一样先取模再落盘。

## 六、自动连接（零配置）

两种形态，都由**宿主**判定与选块，界面只描述结果：

### 拼块自动连接（`a2quad`，RPG Maker A2 / `ぴぽや [A]` 那种）

识别条件：`imageHeight === 5 × 格子高` 且 `imageWidth % 格子宽 === 0`。
一张 64×160 的图 = 2 个变体 × 5 个形状，每个 32px 逻辑块由 2×2 个 16px 小格拼成。

一格的四个象限各自按「左 / 上 / 左上」查同一张 5 状态表（照 AsLib `map20n_Number`）：

| 左 | 上 | 左上 | 形状 |
|---|---|---|---|
| 否 | 否 | * | 0（孤岛） |
| 否 | 是 | * | 1 |
| 是 | 否 | * | 2 |
| 是 | 是 | 否 | 3（内角） |
| 是 | 是 | 是 | 4（满格） |

四个象限分别是 TL(left, up, upLeft) / TR(right, up, upRight) / BL(left, down, downLeft) /
BR(right, down, downRight)。所以渲染一格会下发 **4 条 op**，每条贴一个小格。

⚠️ **一条容易写错的约定**：调色板里 A2 素材**只出一个笔刷**（`MapViewTileset.palette` 只有 1 条，
缩略图取「形状 4（满格）× 变体 0」那个 32×32 整块）。用户点它画下去，写进图层数据的是那一小格的
**代表序号** —— 渲染时 `maprender` 会认出「这个序号所属的素材 `shape === "a2quad"`」，再按邻域现推
四个象限的形状号、发 4 条 op。**少了这条展开分支，自动连接笔刷只会画出 16px 的一个小格，而且不报错。**

> 这是 AsLib 最值得抄的一点：**用户什么规则都不用配**。素材图的形状顺序就是规则，
> 而我们连顺序都不用问 —— 它由图片尺寸推出来。

### 整格自动连接（`corner16`）

给「一套 16 块、每块一格的整格素材」用：位序 `N=1, E=2, S=4, W=8`。
导入时若用户把形态选成「整格自动连接」且块数恰为 16，宿主**一次性按位序算好掩码**
（不需要用户点「按顺序分配」）。缺掩码时回退到 Hamming 距离最近的已配掩码
（并列取最小），**绝不留空** —— 留空在网格地图上就是一个透明洞，而且不报错。

### 动画

- **A2 素材的「变体」就是帧**：`cycle` = 各变体下同一象限的小格序号。AsLib 的水就是这么动的。
  界面上不用选，卡片会写明「拼块自动连接本来就是会动的：N 种变体轮流换」；
  只有 1 种变体时说明「横向多画一列变体就会动」。
- **普通 / 整格素材**用「每一行是一帧」（同列同块），界面上叫**「翻页图」**
  （素材卡的「会动吗」里选：不动 / 翻页图）。名字是给非专业用户的比方 —— 像手翻书，
  每一行是一页，连着播就动起来；内部字段是 `animRows`。
  卡片会实时写明结果：「会动：N 行 = N 帧」，只有 1 行时明说动不起来。
  ⚠️ 上传入口（`importMapTileset`）不带 `animRows`，默认是关的 —— 只能在素材卡里开；
  这个开关走 `saveMapTileset({animRows})`（wire 里早就有这个字段）。
- `RenderPlan` 带 `fps`（默认 1，AsLib 是 60 帧 ≈ 1 秒切一次；界面有 慢/中/快 三档）与
  `frameCount`；每条 op 带自己的 `cycle`，**四象限共用同一个全局帧号**。
- 界面只维护一个全局帧号，逐 op 取 `cycle[帧号 % cycle.length]` 去 `legend` 查矩形 ——
  这仍然不是「客户端挑图」：选哪些图进循环是宿主定的，界面只推时钟。

## 六点五、素材卡片与保存时机（用户定的两条产品规则）

**① 素材 = 列表 + 新增，属性在新增那一刻定死。**

「素材」点开是一张列表（每行：名字 / `格子W×H · N 块` / 会动的标「会动 N 帧」 / 内置的标「自带」 / 删除），
加「新增素材」「AI 生成素材」两个按钮和一个「恢复默认素材」按钮。

- 新增走对话框：**素材图 / 叫什么 / 格子大小 / 这块素材怎么用 / 会动吗**，一次填完。
  留空的项走自动识别（`importMapTileset` 的 `cell` / `shape` / `animRows` 可选参数；
  在**量到真实尺寸之后**才套用户的值，不合法就明确拒绝 —— `normalizeCell` 是抛错的，
  所以校验放在写文件之前，免得留下孤儿图）。
- 列表里**没有**任何「改格子 / 改形态 / 改动不动」的入口。宿主对**内置素材**
  （`tileset.builtin`，由 `importSampleTileset` 打上）也会直接拒绝 `saveMapTileset`；
  自己新增的素材宿主仍允许改（对话面 agent 修自动识别错误要用），只是界面不给入口。
- 内置素材默认在列表里：从界面新建项目时，客户端建完就调一次 `importSampleTileset`（本机现算、零成本，
  同名跳过）。它同样可以删，「恢复默认素材」把缺的补回来 —— 也是同一个方法，同名不会变成两份。

**①.5 「AI 生成素材」：**生成交给一个新对话，属性仍然由用户在「新增素材」里定死。**

- 对话框只收五件事：**提示词 / 素材名字 / 动画帧数（默认 1 = 静态）/ 动画生成方式（生图模型 | 视频模型）/
  这块素材怎么用（自动判断 | 普通 | 整格 | 拼块）**。
- 点「生成」不在这里生成任何东西：客户端**开一个新对话**（`sessions.create({})`，不给 workspaceId / cwd
  = 不挂靠任何项目），切到对话界面，把拼好的需求作为第一句话发进去（`buildAssetRequestPrompt`）。
- **用法（普通 / 整格 / 拼块）在生图之前就定好**：默认让对话里的 agent 按判据自己判断
  （成片铺开、边缘要自动接上 → 拼块；要连成一条、拐角要对上 → 整格；一块一块单独摆 → 普通），
  用户也可以在那个控件里替它拍板。提示词按这个用法写清**画什么**：
  普通 = 每张一格内容；整格 = **一块**正方形、四边都能接上自己的无缝墙砖（整张图就是这一块）；
  拼块 = **每个变体一块**同样的无缝材质。
  ⚠️ **不能让模型画多格排布**：一排墙在地图上用到的是三块不同的图块，而模型画的格子是各自独立的
  （灯带 / 板缝各偏几十像素），拼起来每处交界都是硬缝 —— 实测边缘差 201、块内相邻列才 58。
- 对话里的 agent 按提示词生成（帧数 1 = 一张图；帧数 > 1 + 生图模型 = 同提示词出多张；
  + 视频模型 = 先出静态首帧，再图生视频抽 N 帧），然后调 `composeMapAsset` 把图按**同一个用法**整理成一张：
  普通每张中心裁到**当前地图网格**再竖排成翻页图；整格 / 拼块都**从同一块砖的像素拼出全部格子**
  （`corner16SheetFromTile` / `a2SheetFromTiles`），「断」的那几边由代码压一道收口 ——
  凡是「连」的边都是同一块砖的边缘，所以一排墙 / 一片水不会出现接缝。落在项目的 `ai/` 暂存区。
  **这一步不碰素材列表**；这块砖自己接不上自己时，结果里会附一句提醒（平铺会有缝、建议重画）。
- **一格多大（地图网格）在新建项目时定**：16 / 32 / 48 / 64（默认 32），项目级、之后不能改。32 一格时 2K 的 AI 素材
  必然被压扁；要真清楚就开 48 / 64。内置素材会按网格比例缩放，AI 素材按网格出块，导入时格子与网格不一致会给明确告警。
- **模型留的白框会被自动裁掉**（只裁浅色薄边，深色平底 / 纯色图不动），裁了多少写进结果说明里。
- **素材属性可以改**：点素材列表里的一行弹出「素材属性」窗口，能改**名字 / 播放速度 / 循环方式**（内置素材也行）。
  这三样不动图块，改完地图上画过的格子不用重画；形态与格子大小仍然一次定死（要换只能删掉重加）。
- **整图的占格上限 = 地图自己**：一张整图最多和整张地图一样大（比地图大就明确报错），不再死写 8 格。
- **「整图」（多格印花）**：一张图一次占 N×M 格（雕像 / 壁画 / 地毯）。导入时选「整图」并填「占几格」与
  「帧数」，再逐格点**通行区域**（不可通过 / 可通过·被人物遮挡 / 可通过·遮挡人物，另有「全部不可通过 / 全部可通过」两键）。
  整图是「立在格子上的物件」，所以背景要透明：AI 生成时提示词会要**纯绿幕 + 只画建筑本体（不要地面）**，
  「新增素材」里的「抠掉绿幕背景」默认勾着，导入时自动抠成透明（自己导透明 PNG 也能勾，没有绿就什么都不做）。
  印的时候**点一次印一整张**（拖动不连印），**右键转 90°**（0→90→180→270），笔刷框跟着转；擦除只能用「橡皮」工具，
  碰整图一格就整张摘掉（会有提示，撤销一步整张还原）。设置里的「区域」开关把每格通行性按颜色叠加出来，导出的
  `map.json` 带上每格的 `pass`，游戏引擎拿去做寻路与遮挡。
- **「循环方式」在「新增素材」里选**（正放 / 倒放 / 来回，只对会动的素材出现）：三者都是把帧序展开
  （正放 0→1→2→3；倒放 3→2→1→0；来回 0→1→2→3→2→1，接缝不跳），跟播放速度一样属于表现层，之后也能改。
- **「清晰度」在「新增素材」里选**（平滑 / 锐利 / 清晰）：AI 给的是 2K 大图、一格只有 32px，缩法不同出来的细节差很多。
  为了让它有用，`composeMapAsset` 会先按 **4 倍分辨率**把素材图留在 `ai/` 里（不回链成 32px 一格的碎图），
  导入时才按选的清晰度缩到格子大小 —— 所以「新增素材」里会显示一行「这张图每格 128px，会缩到 32px」。
  自己导一张格子大小的图（绝大多数手动导入）时这一项不出现，图逐字节原样存。
- **每张素材可以有自己的播放速度**：「新增素材」里有一个「动画速度」下拉（跟设置里的全局速度 / 1 / 2 / 4 / 6 / 8 / 12 帧每秒），
  只对会动的素材出现；素材列表上会标出来（「会动 N 帧 · X 帧/秒」）。它不动几何、不动序号，所以之后也能改（`saveMapTileset({fps})`，清成 `null` 就回全局）；
  没单独设的素材跟着「设置 → 动画速度」那条全局速度走 —— 一张地图上不同的素材可以各走各的。
- **会动的只有两种用法**：拼块（帧数 = 变体数，地图上按变体循环，既自动连接又会动）与普通（帧数 = 翻页图的行）。
  整格 4×4 全是接法、**没有帧这一维**，所以在对话框里选整格会把帧数灰掉、视频模型点不动（并提示改用拼块），
  派活的提示词也会把参数归一到静态、并要求 agent 把这件事写进回答 —— 不能再出现「用户配了动画、结果静默不动」。
- 工具返回的 `openUrl` 带 `dialog=add&asset=ai/<名字>.png&frames=<N>&shape=<用法>`：用户点开就落在地图编辑器、
  素材窗口展开、「新增素材」已经打开并预填（图 / 名字 / 格子 / **用法 = 回链里的形态** / 会动吗按形态定）。
  用法必须照抄回链里的 `shape`：写死「普通」会让拼块 / 整格的图被当成普通素材导入（画出来全是碎块），
  而留给「自动识别」也不行 —— `32×(32×5)` 这种竖条会命中「高 = 5 × 格子」的判据，
  自动识别会把翻页图认成拼块。两处都不报错、只是画不对。
- 所以「属性在新增那一刻定死」这条规则没有被绕过：AI 只负责把图做好，**由用户确认那一次**才导入。

**② 保存时机：一笔画完才提交一次；但拖动期间要看得见（预览）。**

拖动期间**只攒 op**，到 `pointerup` / 指针离开 / 被取消时提交一次（原来按 40ms 分批提交，
一笔能发几十次）。一步完成的编辑（油漆桶 / 一键生成）走 `immediate`，立刻提交。

**「看得见」靠宿主预览，不靠客户端自己画**：`mapPlan` 支持 `pending` ——
把这些还没提交的 op 盖到一份 `cloneDoc` 上算出计划（走**同一个 `applyOps`**，
所以预览和提交后的结果逐字段一致），**不 `pushHistory`、不写盘**。
客户端每 ~80ms 带一次 `pending` 查计划，于是拖动过程中格子就出现了。

- ⚠️ **预览查询一律不带 `have`**（说自己什么都没有）。真机踩过：预览改的格子往往落在
  已经缓存过的块里，宿主一看「你有这一块」就不回传 —— **拖了一路什么都没有**，松手提交后
  靠 `dropKeys` 重拉才出现。客户端又不许自己算「这一笔碰到哪些块」（那是宿主的几何），
  所以预览时干脆要一整份可视块（多传几十块，换「拖着就能看见」）。宿主那边另有
  `forced`（按 `pending` 的脏块强制回传）作为第二道保险。
- 预览块要**记下来并在提交时标成待重拉**（`previewKeys`）：它是按「当时那一部分 op」算的，
  最后几个格子可能还没进去。提交后宿主按真实数据重发这几块，画面不会停在预览上。
- 预览响应回来时如果这一笔已经提交/结束了，**直接丢掉**（`strokeAtQuery` 对比），
  否则缓存会停在过时的预览内容上。
- 顶栏原来那个「正在保存… / 已自动保存 HH:MM」整块删掉了（用户：画的时候一直闪，不需要）。
- ⚠️ **卡片里没有「确定」按钮**（曾经是「标记这一步看过了 + 收起卡片」）。用户的判断很直接：
  「确定键可以删了，和右上角的 x 没区别」——这是对的：上一版为了去掉「取消确认」把它做成了
  普通按钮（不是勾选式、也没有反向操作），于是阶段标记在界面上**完全不可见**，
  按与不按看起来一模一样，那颗按钮就只剩「关掉卡片」一个作用。
  现在关卡片只有右上角的 ×；阶段标记仍可由验收流程 / 对话面（`setMapApproved`）改，
  界面上唯一还暴露它的是设置卡片里那颗**有状态**的「整个模块看过了」（`data-on` 会变色，
  一次把四个阶段一起打）。

## 七、界面必须复刻的那点几何

只有四个函数，都在 `src/client.ts` 的模块六段落里，前缀 `MAP_`：

| 函数 | 用途 | 宿主对应 |
|---|---|---|
| `MAP_pointToCell` | 指针命中（含环绕取模） | `mapgeom.pointToCell` |
| `MAP_cellAnchor` | 格子锚点 | `mapgeom.cellAnchor` |
| `MAP_cellTopLeft` | 贴图左上角 | `mapgeom.cellTopLeft` |
| `MAP_lineCells` | 拖动补间（不能漏格） | `mapdoc.lineCells` |

**判据不是「我推的公式对不对」，而是「与宿主真实现逐点相同」**：
`scripts/verify-map-client.mjs` 拿宿主的真函数对同一组输入逐点比对（环绕与非环绕两组 ×
整张地图采样 + 边界 + 图外点），再加上「画布 drawImage 调用序列 == 宿主计划」这条逐项契约。

除此之外，界面里**不许**出现变体挑选、形状/掩码归约、绘制顺序、chunk 计算、坐标变换
（`verify-map-client.mjs` 最后一次扫源码拦）。

### 图层卡（点图层格中间的数字打开）

```
┌ 图层 ────────────────────────────┐
│ ●  标记层      3 个标记     [标记] │  ← 固定一行：不可改名 / 删 / 移
```

## 九、导出规范

界面上是**一次选完 → 一次导出 → 一次下载**：内容是三只复选框（地图图片 PNG /
存档数据 JSON / 素材原图），执行只有一个「导出」按钮，倍率只在勾了 PNG 时出现。
（老版本是「导出图片 PNG」「导出存档 JSON」两个按钮并排，一个看着像被选中的页签、
另一个点下去却是立即执行 —— 选择与执行混在一起，用户原话是「意味不明」。）

产物：

- `map.png`：按绘制计划光栅化（最近邻整数缩放，倍率 1×–4×）。
- `map.json`（`dsh-gem-map@3`）：

```jsonc
{
  "format": "dsh-gem-map@3",
  "grid": { "tileWidth": 32, "tileHeight": 32, "wrap": true },
  "cols": 32, "rows": 32,
  "tilesets": [{ "id", "name", "image", "cell", "shape", "variants", "tileCount" }],
  "legend":   [{ "index", "tilesetId", "rect" }],
  "layers":   [{ "name", "data": [ …语义序号… ] }],
  "markers":  [{ "n": 1, "name": "宝箱", "r": 3, "c": 3 }]
}
```

`markers` 是**源数据**（位置 + 名字），`map.png` 里**不画标记** —— 引擎按坐标自己渲染。
`n` 写出来只为让人一眼对得上界面上的数字（= 数组下标 + 1）。

`layers[].data` 是**语义值**（全局图块序号），不是解析后的贴图 —— 自己格式要能继续改。

- `tilesets/**`：勾了「素材原图」才拷。拷进去的相对路径与 `map.json` 里的 `image`
  同形（都是 `tilesets/<id>.png`），所以**导出目录搬到别处也能用**（整包自包含）。
- `<地图名>.zip`：产物超过一个就自动打一个包（`formats.zip:false` 可关）。
  界面上的主下载按钮指向它 —— 一次点击拿走全部，而不是让浏览器连下好几个文件。
  `manifest.json` 是我们自己的账本，**不进 zip**。
- `manifest.json`：文件清单 + 尺寸 + 告警。

三条口径：

1. **每次导出先清空这个导出目录**：`export/<安全名>/` 整份是生成的，不清的话
   「上次导了 JSON、这次只导 PNG」会留下一份过期的 `map.json`，用户打开文件夹看到的
   东西和界面上列的清单对不上。
2. **zip 的时间戳写死**（1980-01-01）：同一份文档两次导出逐字节一致（有断言盯着）。
3. **文件落在哪要写出来**：卡片上给出导出目录的**本机绝对路径**，「打开导出目录」
   打开的也是这个目录（以前打开的是项目根目录 —— 那里并没有他要的文件）。
   想自己挑位置就点「另存为…」（浏览器原生保存框，没有这个 API 时退回普通下载并说明）。

## 十、一键生成

AsLib 的库里实现了随机 / 迷宫 / 大陆三种地图生成，但它的界面没有接。本模块接上
（用户明确要求），三种算法自研、纯本地、同种子结果逐字节可复现：

| 种类 | 做什么 | 参数怎么来 |
|---|---|---|
| 随机铺满 | 整层在选中的图块里均匀随机 | 至少选 1 块 |
| 迷宫 | 奇数边长上的迭代 DFS 挖洞（AsLib `asMazeMapMake` 同款） | `tiles[0]` = 墙、`tiles[1]` = 通路 |
| 大陆 | 17×17 菱形四角（under/sea/green/snow）递归插值 + 种子，再放大 | 按选择顺序映射 4 种地貌 |

生成走一次 op 提交（可一次撤销）。

## 十一、内置素材

AsLib 自带的 `Picture/MapChip/*_pipo.png` 是**第三方版权素材，不打包**
（其 README 写明 "Third party content is copyrighted by its respective owners"）。
所以内置素材自己产：`src/mapsamplegen.ts` 程序化生成

- 4 张 A2 图（草地 / 土路 / 水 / 石墙，`64×160`，2 变体 × 5 形状 × 32px，水带 2 帧动画），
- 1 张道具网格图（树 / 花 / 石头 / 木箱 / 栅栏 / 蘑菇 / 断枝 / 石头堆）。

确定性（同输入两次渲染逐字节一致）、零外部请求、零计费。
`scripts/make-map-sample-tileset.mjs --ark` 可以改用火山引擎 Seedream 生成纹理
（生成后写进 `src/mapsample.ts` 的 `SAMPLE_TEXTURE_OVERRIDE`，同一条本地合成管线），
这一步真实计费、需要显式 `--yes`。

## 十二、对话调用面

模块六**全本地**，所以 `game_material({action:'intake'})` 对 `module=map` **故意不加 API Key 阻塞**。

agent 可以直接画地图、也能一键生成：

```js
applyMapOps({ projectId, ops: [
  { kind: "paint",   layerId: "l0", cells: [{ r: 5, c: 5, tile: 48 }] },   // tile 0 = 清空
  { kind: "fill",    layerId: "l0", r: 0, c: 0, tile: 48 },
  { kind: "rect",    layerId: "l0", r0: 2, c0: 2, r1: 6, c1: 6, tile: 48, filled: true },
  { kind: "replace", layerId: "l0", from: 48, to: 12 }
] })
runMapGenerate({ projectId, kind: "maze", tiles: [48, 0], seed: 7 })
```

`tile` 用 `getMapProject` 的 `legend[].index`（从 1 开始，0 = 空）。
返回体里带 `dropKeys`，所以 agent 也能判断「这一笔让哪几块缓存失效」。

标记点同样能画（走同一个 `applyMapOps`）：

```js
applyMapOps({ projectId, ops: [
  { kind: "marker", op: "add",    r: 3, c: 3, name: "宝箱" },
  { kind: "marker", op: "rename", id: "m1", name: "出口" },
  { kind: "marker", op: "move",   id: "m1", r: 4, c: 4 },
  { kind: "marker", op: "remove", id: "m1" }
] })
```

图层改名 / 换顺序走 `saveMapDoc`（`layers` / `addLayer` / `removeLayerId` / `moveLayer`）。

## 十三、验收标准（可度量）

| # | 判据 | 阈值 | 谁在盯 |
|---|---|---|---|
